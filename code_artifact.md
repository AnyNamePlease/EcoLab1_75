# Отчет по проекту и описание тестов: EcoLab

## 1. Введение и общие сведения

Настоящий документ представляет собой итоговый отчет по выполнению проекта **EcoLab** и описание проведенного комплекса тестирования. Проект направлен на мониторинг экологических показателей и анализ данных с датчиков окружающей среды.

*   **Статус проекта:** Завершен
*   **Тип отчета:** Технический отчет и протокол тестирования
*   **Дата формирования:** Октябрь 2026

---

## 2. Структура проекта

Проект включает в себя следующие ключевые модули:
1.  **Модуль сбора данных (Collector):** Интеграция с IoT-устройствами для получения телеметрии в реальном времени.
2.  **Модуль анализа (Analyzer):** Обработка поступающих данных, выявление аномалий и превышений пороговых значений (например, уровня $CO_2$ или радиационного фона).
3.  **Пользовательский интерфейс (Dashboard):** Веб-приложение для визуализации графиков и формирования сводных отчетов.

---

## 3. Описание тестов

Для обеспечения стабильности, надежности и точности расчетов системы EcoLab был разработан комплекс автоматизированных и ручных тестов.

### 3.1. Модульное тестирование (Unit Tests)
Модульные тесты проверяют корректность работы отдельных функций и классов в изоляции.
*   **Тест расчета индексов загрязнения (`test_pollution_index`):** Проверка правильности математических формул расчета интегрального индекса качества воздуха по формуле:
    $$I = \sum_{i=1}^{n} \frac{C_i}{MPC_i}$$
    где $C_i$ — концентрация вещества, а $MPC_i$ — предельно допустимая концентрация.
*   **Тест валидации входных данных (`test_data_validation`):** Проверка отсеивания некорректных или отрицательных значений датчиков.

### 3.2. Интеграционное тестирование (Integration Tests)
Проверяют взаимодействие между модулем сбора данных и базой данных.
*   **Тест сохранения потока данных (`test_db_persistence`):** Симуляция отправки пакета данных от 50 датчиков одновременно с последующей проверкой целостности записей в базе данных.

### 3.3. Нагрузочное тестирование (Load Tests)
*   **Тест производительности API (`load_test_api`):** Проводился с использованием инструмента нагрузки для симуляции одновременного запроса от 500 активных пользователей и датчиков. Система продемонстрировала среднее время отклика менее $120$ мс при пиковых нагрузках.
